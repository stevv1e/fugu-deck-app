# Проверка модуля fd-secure на реальных телефонах

Модуль `modules/fd-secure` (Swift и Kotlin) ни разу не компилировался: для iOS нужен Xcode на Mac, для Android — Android SDK
и доступ к Maven/Google. Всё остальное приложение проверено (README, «Что проверено»), но **ключи в чипе, биометрия
на подпись и mTLS из чипа работают только после этих проверок.** Без модуля приложение работает на программных
ключах (Expo Go) — это режим разработки, не боевой.

## Что нужно

| | iOS | Android |
|---|---|---|
| Машина | Mac с Xcode 26+ | любая ОС с Android Studio (SDK 36) |
| Телефон | iPhone с Face ID / Touch ID, iOS 18+ | телефон с отпечатком; лучше со StrongBox (Pixel 6+, Samsung S21+) |
| Аккаунт | Apple Developer (для App Attest на устройстве) | — |
| Сервер | одиночный Fugu Deck с `MTLS_MODE=required` (README, «Одиночный сервер: что настроить») | то же |

```bash
cd mobile && npm install
npx expo run:ios --device        # или: npx expo run:android --device
```

## Чек-лист

Отмечайте результат; при расхождении — пришлите вывод (Xcode / `adb logcat | grep -i fdsecure`).

### 1. Сборка
- [ ] iOS: проект собирается без ошибок Swift; приложение запускается на устройстве.
- [ ] Android: сборка Gradle проходит; приложение запускается.

### 2. Ключи в чипе
- [ ] «Настройки → Что защищает ключи»: iOS — **Secure Enclave**; Android — **StrongBox** (или **TEE** на телефонах без StrongBox).
- [ ] Регистрация на сервере проходит; в «Сервер и устройства» у устройства `key_storage` = то же значение.
- [ ] На сервере `GET /api/devices` показывает `key_storage` не `software`.

### 3. Биометрия на КАЖДУЮ подпись
- [ ] В чате попросите агента сделать коммит → карточка подтверждения → «Разрешить» **спрашивает Face ID / отпечаток**.
- [ ] Второе подтверждение подряд **снова** спрашивает биометрию (не кэшируется).
- [ ] «Отклонить» в диалоге биометрии → подтверждение не отправлено, агент продолжает ждать.
- [ ] Добавьте новый отпечаток / лицо в настройках телефона → следующая подпись **не проходит**, приложение просит
      зарегистрировать устройство заново (ключ подтверждения инвалидирован — так и задумано).

### 4. mTLS ключом из чипа
- [ ] С `MTLS_MODE=required` приложение работает (чаты, поток ответа).
- [ ] В журнале сервера у запросов есть `X-Client-Cert-Serial`, совпадающий с серийным номером в «Сервер и устройства».
- [ ] С другого устройства (или `curl` без сертификата) тот же адрес **обрывает TLS**.
- [ ] Поток ответа агента (SSE) идёт через нативный транспорт: ответ появляется по частям, а не целиком в конце.

### 5. Аттестация

Одиночный сервер аттестацию только сохраняет. **Кластер (keyguard) её проверяет** — этот раздел важнее всего пройти на
настоящих телефонах: проверка написана по спецификациям и сверена с одной настоящей цепочкой Google, но принимаемую
аттестацию без реального устройства не построить. keyguard запускать с `DECK_ATTESTATION=required`, `DECK_ANDROID_PACKAGE`,
`DECK_ANDROID_CERT_SHA256` (SHA-256 сертификата подписи сборки), `DECK_APPLE_APP_ID` (`<TeamID>.<bundle id>`).

- [ ] Android: вход в кластер проходит, в ответе регистрации и в статусе `attested: android-key/strongbox` (или `/tee`).
- [ ] Android: в журнале keyguard нет `device.attestation_rejected`. Если есть — записать причину и модель телефона:
      чаще всего это особенности цепочки производителя (сроки сертификатов, нет StrongBox, поле приложения).
- [ ] Android: ключ подтверждения принят (требование биометрии видно в аттестации) — причина отказа «не требует биометрии»
      означает, что тег биометрии лежит не в аппаратном списке; сообщить модель.
- [ ] Android: отладочная сборка (другой сертификат подписи) отклоняется с причиной «подписано чужим ключом».
- [ ] Android: телефон с разблокированным загрузчиком отклоняется.
- [ ] iOS: вход проходит, `attested: apple-app-attest/app-attest` (сборка TestFlight/App Store; сборка из Xcode даёт
      среду разработки — она принимается только с `DECK_APPLE_ATTEST_DEVELOPMENT=1`).
- [ ] iOS-симулятор и Expo Go: при `required` регистрация отклоняется, при `optional` проходит без отметки.
- [ ] Повторный вход тем же телефоном через 20 минут после получения вызова: приложение берёт новый вызов.

### 6. Отзыв и потеря
- [ ] Отзовите устройство с другого телефона → на отозванном следующий запрос возвращает «устройство отозвано».
- [ ] Удалите приложение и поставьте заново → ключей нет, нужна новая регистрация (ключи не переживают удаление).

### 7. Кластер v2 (когда поднят тестовый кластер)
- [ ] QR-приглашение `fugudeck://join?…` открывает экран входа (и из сканера, и по ссылке).
- [ ] Браузер ведёт в Keycloak, вход по **passkey**, возврат в приложение без ошибок.
- [ ] Устройство «ждёт подтверждения»; после подтверждения пригласившим «Проверить» → «подтверждено», сертификат установлен.
- [ ] Ввод ключа API спрашивает биометрию и показывает маску ключа; запрос идёт по mTLS на `api.<домен>`.

## Известные риски, которые этот чек-лист должен снять

- iOS: `SecIdentity` из ключа Secure Enclave + сертификата для `URLSession` — самое рискованное место (раздел 3.2
  архитектуры). Если не работает, запасной путь — ключ mTLS в Keychain без экспорта (`ThisDeviceOnly`), а ключ сессии
  в Secure Enclave — только для DPoP.
- Android: `X509ExtendedKeyManager` с ключом из Keystore в OkHttp; `BiometricPrompt` с `CryptoObject` на старых версиях.
