# Интерфейс и маршрутизация Fugu Deck

Актуально для приложения **0.12.0**. Документ описывает пользовательскую навигацию и правила сохранения функций при её изменении.

## 1. Основной принцип

Интерфейс разделён на два состояния:

1. **Главное меню** — подключения, вход и регистрация.
2. **Рабочая область** — чаты, проекты и настройки конкретного пространства.

Возврат в главное меню не является выходом: сессия, ключи и сертификат устройства сохраняются.

## 2. Главное меню

На главном экране находятся:

- добавленные пространства и серверы;
- статус подключения и устройства;
- вход для уже добавленного сервера;
- QR и ссылка-приглашение;
- регистрация нового пространства;
- компактный вход в параметры приложения.

Здесь нет настроек агентов, моделей и чатов: они относятся к открытому пространству.

### Запуск пространства

После выбора подключённого сервера открывается `/launch/[sid]`:

1. проверка ключей и сертификата;
2. создание/обновление защищённой сессии;
3. запуск пространства и проверка доступа к проектам;
4. переход в чаты.

На экране есть «Повторить» при ошибке и «В главное меню». Неуспешный запуск не удаляет прежнюю регистрацию.

## 3. Разделы рабочей области

### Главное меню

Всегда доступно через бренд/домик Windows и пункт меню Android. Содержит подключения и авторизацию.

### Чаты

Старые маршруты `/s/[sid]/chats`, `/s/[sid]/c/[cid]` и `/s/[sid]/tasks` сохраняются.

Доступны: все чаты, streaming, остановка, вложения, модели чата, подтверждения, активные/завершённые запуски и уведомления. На Windows «Запуски» — вложенный пункт sidebar.

### Проекты

Старые маршруты `/s/[sid]`, `/p/[pid]`, `/kb/[pid]`, `/sched/[pid]` и `/workspace` сохраняются.

Включают: проекты и режимы, создание/импорт/экспорт, базу знаний, расписания, файлы, Git diff, CI и ручной SSH. На Windows Workspace — вложенный пункт; на Android — отдельная ссылка в «Ещё».

### Модели

Использует существующий `/s/[sid]/prefs?tab=models`.

Содержит каталог, провайдеров, поиск, избранное, недавние, роли, fallback и обновление `/models`.

### Сервера

Для кластера ведёт в `/servers/[cid]`, для standalone — `/s/[sid]/settings`.

Здесь SSH-серверы, устройства сервера, отпечаток, отзыв, выход и журнал. Подключения самого приложения остаются в главном меню.

### Доступы

- `/keys/[cid]` — AI/Git ключи;
- `/cluster/[cid]` — все интеграции кластера, включая Drive;
- `/mcp/[cid]` — MCP;
- `/egress/[cid]` — разрешённые домены.

В standalone провайдеры открываются через существующий экран моделей. Секреты после ввода не раскрываются.

### Разрешения

- `/s/[sid]/prefs?tab=agents` — права агентов standalone;
- `/cluster/[cid]`, `/devices/[cid]` — устройства и pairing;
- `/team/[sid]`, `/teams/[cid]` — участники и роли;
- `/s/[sid]/skills` — скилы.

Подтверждения и опасные действия не отключаются навигационными настройками.

### Параметры

`/settings` содержит темы, уведомления, состояние ключей устройства, сведения о сборке и вход в модули.

`/modules` включает каталог, конструктор, безопасность, экспорт и E2EE. Расходы остаются на `/s/[sid]/usage` и доступны через меню/командную палитру.

## 4. Android

Нижние вкладки:

- Чаты;
- Проекты;
- Модели;
- Ещё.

«Ещё» содержит главное меню, Workspace, задачи, репозитории, серверы, доступы, разрешения, скилы, расходы, модули и параметры. Для текущего проекта дополнительно показываются его чаты, база знаний и расписание.

Главное меню, авторизация, pairing и детальный чат остаются полноэкранными — нижняя панель там не занимает место.

## 5. Windows

DesktopShell использует текстовую sidebar:

- Главное меню;
- Чаты;
- Проекты;
- Модели;
- Сервера;
- Доступы;
- Разрешения;
- Модули;
- Параметры.

Панель можно свернуть до иконок. Workspace, запуски и все интеграции отображаются вложенными пунктами. Последнее пространство сохраняется при переходе в глобальные параметры/модули.

Дополнительно доступны:

- Ctrl+K — все разделы, интеграции и пространства;
- Ctrl+N — существующий переход к проектам;
- Ctrl+Alt+T — Workspace;
- панель чатов и контекстная панель;
- системные кнопки окна и уведомления Electron.

## 6. Чат и прокрутка Windows

Центральная колонка сообщений ограничена по ширине, composer остаётся снизу и визуально связан с этой колонкой. Логика отправки, остановки, вложений и подтверждений не меняется.

Scrollbar тонкий, с прозрачной дорожкой и появляющимся при наведении ползунком. Колесо, клавиатура и перетаскивание ползунка сохраняются.

Автопрокрутка выполняется только когда пользователь находится у нижней границы. При чтении старых сообщений поток не дёргает экран; кнопка со стрелкой возвращает к последним сообщениям.

## 7. Совместимость маршрутов

Старые URL не удалены. QR, push, OAuth return, `fugudeck://` и прямые ссылки продолжают вести на прежние экраны. Новая структура сначала меняет оболочку, а не бизнес-логику.

`mobile/src/core/navigation.ts` содержит реестр разделов и `ROUTE_INVENTORY` с сохранёнными функциями. `mobile/tests/navigation.test.ts` проверяет:

- наличие всех продуктовых областей;
- пути с текущим пространством;
- standalone/cluster/team варианты;
- полноэкранную авторизацию и детальный чат;
- Android fallback и Windows разделы.

## 8. Правило дальнейших изменений

При перемещении кнопки нельзя копировать её API-логику в новый компонент. Нужно переиспользовать существующий экран/component и добавить маршрут в реестр. Для каждого удаляемого из оболочки пункта должен быть новый явный путь к той же функции.
